Communication¶

Research question¶

How does the link model — delay distribution, loss, bandwidth — affect end-to-end latency and application outcomes in a cooperative autonomy stack?

Layers involved¶

  • Data Source — any source

  • NetWaggle — link backend and distribution

  • Analysis — frame latency, link statistics report

What to configure¶

delay backend (message-level, exact distribution):

Constant delay link — docs/snippets/delay-link.yaml¶
# Valid delay-link snippet: constant 60 ms message-level delay.
# Use mode: delay when you want the configured distribution honoured exactly.
extends: ../../configs/base.yaml

experiment: {name: snippet_delay, app: reference, repetitions: 1}
source: {kind: synthetic, count: 8, width: 64, height: 48}
nodes:
  - {name: client, host: localhost, role: client, device: cpu}
  - {name: server, host: 127.0.0.1, port: 15011, role: server, device: cpu}
links:
  - name: inference_link
    from: client
    to: server
    network:
      mode: delay
      distribution:
        kind: constant
        value_ms: 60.0
app: {plugin: reference, params: {model_kind: stub}}

netem backend (packet-level):

Netem lognormal link — docs/snippets/netem-link.yaml¶
# Valid netem-link snippet: 30 ms mean lognormal, bandwidth_mbps required.
# p99 = 30 * exp(1.282 * 0.23) ≈ 42 ms, well within 2 * p50 = 60 ms.
# bandwidth_mbps is required to prevent packet reordering.
extends: ../../configs/base.yaml

experiment: {name: snippet_netem, app: reference, repetitions: 1}
source: {kind: synthetic, count: 8, width: 64, height: 48}
nodes:
  - {name: client, host: localhost, role: client, device: cpu}
  - {name: server, host: 127.0.0.1, port: 15012, role: server, device: cpu}
links:
  - name: inference_link
    from: client
    to: server
    network:
      mode: netem
      distribution:
        kind: lognormal
        p50_ms: 30.0
        p99_ms: 51.6
      bandwidth_mbps: 10.0
app: {plugin: reference, params: {model_kind: stub}}

netwaggle backend (Mininet-WiFi wired; requires cadet emulate):

Netwaggle wired link — docs/snippets/netwaggle-wired.yaml¶
# Netwaggle wired-medium link: constant delay over a Mininet-WiFi wired link.
# Requires cadet emulate (privileged container, Mininet-WiFi).
# Passes cadet validate.
extends: ../../configs/base.yaml

experiment: {name: snippet_netwaggle_wired, app: reference, repetitions: 1}
source: {kind: synthetic, count: 8, width: 64, height: 48}
nodes:
  - {name: client, host: localhost, role: client, device: cpu}
  - {name: server, host: 127.0.0.1, port: 15014, role: server, device: cpu}
links:
  - name: inference_link
    from: client
    to: server
    network:
      mode: netwaggle
      medium: wired           # wired Mininet link (default)
      distribution:
        kind: constant
        value_ms: 20.0
      loss: 0.0
app: {plugin: reference, params: {model_kind: stub}}

See Configure link distributions for the full field reference and when each backend applies. Key constraint: netem and netwaggle cannot render distributions where p99/p50 exceeds 2×; the delay backend has no such restriction.

Sweeping over link delay:

Sweep over delay values — docs/snippets/sweep-link-delay.yaml¶
# Sweep example: constant delay values. Generates 4 run configs.
# Use as a template; replace with lognormal or netem fields as needed.
# Passes cadet validate.
extends: ../../configs/base.yaml

experiment: {name: snippet_sweep_delay, app: reference, repetitions: 1}
source: {kind: synthetic, count: 8, width: 64, height: 48}
nodes:
  - {name: client, host: localhost, role: client, device: cpu}
  - {name: server, host: 127.0.0.1, port: 15016, role: server, device: cpu}
links:
  - name: inference_link
    from: client
    to: server
    network:
      mode: delay
      distribution:
        kind: constant
        value_ms: 20.0
      loss: 0.0
sweep:
  axes:
    links[0].network.distribution.value_ms: [10, 20, 40, 80]
app: {plugin: reference, params: {model_kind: stub}}

How to run¶

cadet run examples/reference/backends.yaml \
    --set links.0.network.mode=delay \
    --app-module examples.reference.app

For netwaggle (requires the emulation container):

cadet emulate examples/reference/backends.yaml \
    --set links.0.network.mode=netwaggle \
    --app-module examples.reference.app

Where results land¶

outputs/{experiment}/{app}/{run_id}/:

  • {run_id}_latency_location_log.csv — per-frame end-to-end latency

  • {run_id}_link_report.csv — per-link send/receive counts, drop rate, p50/p90/p99 latency

  • run.json — resolved link config

How to extend¶

  • Model a 5G lognormal tail: see docs/snippets/v2v-lognormal-link.yaml.

  • Add loss: set links[0].network.loss: 0.01 (fraction, not percent).

  • Multi-hop topology: add a second links entry between server nodes.
