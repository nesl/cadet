cadet.orchestrator¶

Orchestrator: turn a config into running processes and back again, cleanly.

This module owns the lifecycle of a run and a sweep. For a run it clears its own leftovers, runs preflight, starts the servers and waits for readiness, starts the sim-side hooks and waits for their marker, starts clients/load, waits for the run to end by its experiment.end_on rule, then tears everything down in reverse order so no process is orphaned. For a sweep it enumerates the matrix and runs each cell; with experiment.resume (or --resume) it skips cells whose output is already complete, and by default it reruns them. An interrupted run is part of that lifecycle, not an exception to it: SIGTERM and SIGHUP are turned into an exception (cadet.orchestrator.lifecycle.interrupt_guard()) so the teardown runs, and whatever a harder kill leaves behind is removed by cadet down (cadet.orchestrator.recovery.sweep()). It provides PreflightError, preflight(), RunResult and Orchestrator.

It is called by cadet run / cadet sweep in cadet.cli, and spawns the role entry points (cadet serve / cadet client / cadet load) through the launcher each node’s config asks for: a host process, a container on this machine, or (in dry-run) a container on another machine. cadet.orchestrator.placement owns that dispatch, the per-run docker network and the per-node containers; this module keeps the ordering and the teardown, which do not change with where a role runs. Sim hooks come from the app plugin’s AppPlugin.sim_hooks().

It also records what a cross-node timestamp is worth: with metrics.collectors: clock_offset it measures each node’s clock against its own before the run and again after the roles have stopped, and writes the offset and its uncertainty into run.json (cadet.metrics.clock_offset). Nothing is corrected by it.

It also owns the lifetime of each link’s network backend, installing netem qdiscs before any role starts and removing them on teardown so a failed run cannot leave traffic shaped. For a containerised node the qdisc goes inside that node’s own namespace, through a runner the placement supplies, because the interface to shape is the container’s and not the host’s. The delay backend needs nothing here (it lives inside the transport), and netwaggle is driven by cadet emulate inside the emulation container.

Driven entirely by the experiment config (nodes, nodes.launcher, outputs) plus --app-module / --model-dir passed to role processes.

cadet.orchestrator.runner.preflight(config, model_dirs, log=<built-in function print>, check_ports=True, allow_experimental=None)¶

Check a run can start: model artifacts resolve and listening ports are free.

Raises PreflightError with a readable message on the first problem. Throughput is a warning rather than a problem: a saturated link is a valid experiment, and only the experimenter can say whether this one is intended.

check_ports is False for the emulated backend, whose servers bind inside their own network namespaces: a port busy on the container’s localhost says nothing about the port an emulated host will bind, and refusing on it would reject runs that are fine.

sweep(config_path, overrides, app_modules, model_dirs, reps=None, allow_experimental=None, resume=None)¶

Run every (run_index, rep) cell.

A completed cell is re-run unless resume is asked for, which is what the original did; resume (or experiment.resume) skips cells that already have a run.json.

Cells are separated by experiment.inter_run_pause_s, five seconds as in the original. It is not idle time: on a shared simulator it is what gave the previous run’s actors time to be cleared before the next scenario reloaded the world.

Stops early if a run is interrupted: a terminating signal is a request to stop the sweep, and the cells it never reached are left absent from the output.

down()¶

Remove every CADET-owned leftover; return what was removed.

This is the recovery path for a run that never reached its teardown - a SIGKILL, or a stop before the signal guard was installed. It covers more than the processes it used to: containers, docker networks, emulated namespaces, OVS bridges, veths and the qdiscs a run recorded, each matched by ownership rather than by kind. See cadet.orchestrator.recovery.

Run-lifecycle steps, ported from the original orchestrator scripts.

The original experiment orchestrators already solved the lifecycle of a braking run: clear orphans and the server port, start the server and ScenarioRunner, block on a marker line in the scenario log, run the client to completion, then kill the scenario’s whole process group. This module is that logic, ported once so both the host orchestrator and the emulated session share one ordering and one teardown. Their hard-coded constants (port 10000, script names) became config fields; the readiness marker and its timeout come from the hook’s LaunchSpec. Three behaviours here are additions without an original equivalent: wall-clock limits on each phase (startup_limit_s(), active_limit_s()), treating a sim hook or server failure as the end of the run, and an explicit run-end rule (experiment.end_on). The original’s fuser -k port cleanup was narrowed: only CADET-owned processes are killed; a foreign holder is named by preflight and refused. Used by cadet.orchestrator.runner and cadet.network.netwaggle.session. Phase limits come from experiment.max_startup_s (defaults to the sum of readiness timeouts) and experiment.max_active_s (defaults to source.scenario.timeout_s plus a margin). experiment.end_on and experiment.end_grace_s control when and how cleanly a run stops.

cadet.orchestrator.lifecycle.install_interrupt_guard()¶

Turn SIGTERM and SIGHUP into RunInterrupted; return the undo.

Default SIGTERM handling ends the process immediately, so a finally block never runs and an interrupted run leaves its processes, qdiscs and emulated network behind. Raising instead routes the interruption through the teardown the run already has, which is why this adds no teardown logic of its own. SIGINT already raises KeyboardInterrupt and is left alone.

Returned as a function rather than a context manager because the callers install it around a try/finally they already have, and wrapping that in another block would re-indent the whole run for no behavioural gain; interrupt_guard() is the block form for callers that want one. Signals cannot be installed from a non-main thread, where this is a no-op.

cadet.orchestrator.lifecycle.is_cadet_owned(pid, owned=(), patterns=())¶

True if pid was recorded by this orchestrator and still looks like it.

The record is the evidence of ownership, and a command line cannot replace it: every CADET server’s is cadet serve, so matching on it alone cannot distinguish a leftover of our own from a live process belonging to someone else’s run on the same machine - and killing the latter is what a pre-run cleanup must never do. Measured, before that was narrowed: two orchestrators in one container, and every run of the second failed with the first’s server SIGTERMed during model warm-up.

But a record is not sufficient either, because pids are reused. A stale record names a number, and by the time a later run reads it the kernel may have given that number to something else - including a role belonging to a run in another checkout, which is how this was found: the route equivalence test failed about one run in five with serve:server exited with code -15, while other streams were running their own suites on the same machine. Nothing in the record can notice that; the process can.

So ownership is the record and a command line that still matches one of patterns. With no patterns given the check is the record alone, which is what cadet down wants, where sweeping everything recorded is the point.

A process that looks like a role but is not recorded is reported by looks_like_a_role() and left alone.

Return type:

bool

Parameters:

  • pid (int)

  • owned (Iterable[int])

  • patterns (Sequence[str])

cadet.orchestrator.lifecycle.wait_for_ports_free(ports, timeout_s=5.0, log=<built-in function print>)¶

Wait until every port is actually free, after the holders were killed.

Killing a process does not release its listening socket synchronously, so a bind check run straight after the cleanup still sees the port in use and the run is refused for a port that is about to become free. cadet.orchestrator.lifecycle.kill_orphans(patterns, ports, log=<built-in function print>, owned=())¶

Kill the leftover processes CADET owns, and free only the ports they held.

Ported from the original’s kill_orphans, with its one indiscriminate step narrowed. The original ran pkill -f over its script names and then fuser -k over its port, which frees the port whoever is holding it. Here a port is freed only by killing a holder that is CADET’s own - recorded in owned, or matching one of patterns - so a run can never take down a process the experimenter started.

Every kill is best-effort: “nothing to kill” is the normal case and must not fail the run. Returns the holders left alone, as (port, pid, cmdline), which is what preflight reports when it then refuses the run.

cadet.orchestrator.lifecycle.client_output_failures(out_dir, config=None, log=<built-in function print>)¶

The verdict is the client’s, written beside its metrics: it holds the counts and its app declares what counts as output (see cadet.core.apps.AppPlugin.client_success()). cadet.orchestrator.lifecycle.wait_for_workers(workers, limit_s, guards=(), log=<built-in function print>, sim_hooks=(), end_on='client_report', grace_s=0.0)¶

Block until the run’s end_on rule fires, the limit passes, or a guard dies.

workers are the processes whose completion is the run under the client_report rule (clients and load generators); the original ran its single client in the foreground, which is that rule. guards are processes that must stay alive for the run to mean anything - the sim hooks and the servers - and sim_hooks is the subset whose clean exit can end a run, under the sim_hook_exit and first rules.

Without an explicit rule a clean sim-hook exit only got recorded, so a scenario that had finished left the client streaming into a world that no longer had an ego, until the run limit caught it minutes later. end_on makes the choice a config field instead of an accident of which process happened to exit first, and grace_s gives the workers a bounded chance to write their own report before they are stopped.

Run-state store for cadet status / cadet down.

A JSON record under <cwd>/.cadet/state.json tracks what an orchestrator run has started: a map of run_id -> {dir, procs, netem_interfaces}, with one pid file per launched process under <cwd>/.cadet/pids/<run_id>/<name>.pid. The pid files make ownership checkable: a pattern match on a command line cannot distinguish a CADET role from any other process listening on the same port, so cleanup needs direct evidence that CADET started something; a file written at launch is that evidence, and it persists even if the orchestrator dies mid-run. Used by cadet.orchestrator.runner (records each process at launch and clears on teardown) and by cadet.orchestrator.recovery.sweep() (reads the pid files and interfaces to power cadet down). The state root is fixed at <cwd>/.cadet so cadet status and cadet down need no config.
