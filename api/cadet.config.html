cadet.config¶

CADET configuration package.

What this is for:

The typed configuration layer for CADET experiments: the schema, the typed per-app parameter models, the weather presets, and the loader that applies overrides, expands sweeps and derives run ids.

What it contains:

Re-exports the most-used names so callers can do from cadet.config import Config, load_run_configs, run_id.

How it fits into CADET:

Everything that needs to read an experiment definition (the cadet validate CLI, and later the runner/orchestrator and roles) depends on this package rather than on the legacy cadet/params.py module.

cadet.config.unimplemented_features(config, allow_experimental=False)¶

Return the requested features this codebase will not run.

CADET experiment configuration schema (pydantic, Python 3.8 compatible).

Defines the single, typed shape of a CADET experiment config. A YAML file is parsed into Config; validation errors are turned into readable messages by the loader/CLI. Nothing here executes an experiment: this is the contract every runner, role and launcher reads.

Top-level sections of Config: experiment, source (discriminated union on kind), models, nodes, channels, links (with a typed network model), transport, metrics, app (generic plugin + raw params, validated against the registered plugin’s model by the loader), sweep, outputs, analysis. Plus the leaf models those sections use and the cross-field validators (app/plugin agreement, channel/link endpoints must name existing nodes).

Some options are declared here but not implemented yet (e.g. nodes.launcher: ssh_venv). They validate against the schema and are rejected with a “planned” message by cadet.config.implemented at cadet validate; they are never silently ignored.

cadet.config.loader builds Config from YAML + --set overrides, expands sweep into concrete per-run configs, and derives the run_id. cadet validate reports validation errors against this schema. Author a YAML with the sections above (see configs/*.yaml). Weather is a named preset (cadet.config.weather); model artifacts are per-device in models.registry; swept fields are dotted paths under sweep.axes.

class cadet.config.schema.CarlaClientEgg(**data)¶

Bases: _Strict

Which CARLA client egg a run must use, and where to find it.

name is the egg’s filename, and it is the pin: the Python and CARLA versions are read out of it and checked against the interpreter and the server image (see cadet.orchestrator.versions). host_path is a directory on the machine the role runs on; with it unset the image’s own baked path is used, which is not configurable because it is the image’s convention rather than a machine’s.

The two are separate because one earlier field had to mean both “which egg” and “where the egg is”, and could express neither when they disagreed.

class cadet.config.schema.CarlaSettings(**data)¶

Bases: _Strict

How a run reaches CARLA, and - when it launches one - how it starts it.

host, port and timeout are what every role uses to reach the simulator, and they are what ScenarioRunner is told as well, so the scenario and the client cannot end up on different servers. That was two fields once - the client’s connect port and the launch’s own port, with nothing tying them - and a config could launch a server on one port while the client dialled another, which fails as an ego-attach timeout rather than as a connection error.

port defaults to CARLA’s own 2000, which is the original’s: its client opened carla.Client('localhost', 2000) and run_scenario.sh passed no --port, taking ScenarioRunner’s default of 2000. A run that must not collide with a hand-started server sets another port; preflight already refuses a port held by a process that is not ours, and names the holder.

image is what makes this a launch rather than an attach: with it set the orchestrator starts the server, and without it the simulator is somebody else’s to run.

class cadet.config.schema.DatasetSource(**data)¶

Bases: _Strict

Deterministic dataset replay for model evaluation (the “Dataset Mode”).

Yields one sample per frame, carrying both the input image and the sample’s ground truth in the frame metadata, so a consumer can score a model’s answer against it. Two tasks are supported: vqa (image + question + answers) and detection (image + ground-truth boxes).

With path unset the source generates a small, deterministic, built-in sample set in process: no file, no download and no network, which is what the stub/quick config and the unit tests run on. With path set it reads a manifest (a JSON list of samples) and the images it names from that folder; the example’s fetch_dataset.py writes one from public data.

class cadet.config.schema.TransportTuning(**data)¶

Bases: _Strict

TCP stack settings for one node, applied only in that node’s namespace.

Packet-level backends (netem, netwaggle) let the transport react to the emulated link, and for small paced request/response messages that reaction is large: measured on a 60 ms forward link, the same traffic took 141 ms with kernel defaults and 110 ms with Nagle off. These knobs make that policy explicit instead of inherited.

Every field defaults to None, meaning “leave the kernel’s default alone”. tcp_nodelay is a socket option and works anywhere; tcp_slow_start_after_idle is a per-namespace sysctl and initcwnd a route attribute, so both require the node to own a network namespace (a container or an emulated host) and are refused for a local node, where they would change the host.

Parameters:

  • initcwnd (int | None)

class cadet.config.schema.Connector(**data)¶

Bases: _Strict

A shared medium that nodes attach to, and that runs nothing itself.

A links entry is point to point: one from, one to, and its own qdiscs. A Wi-Fi cell is not that shape. Five stations associating with one access point share one medium, sit in one subnet, and reach each other over the air with no L3 hop and no route between them, which two point-to-point links in series cannot express.

So a connector is infrastructure, deliberately not a nodes entry: there is no role to dispatch on it and nothing binds an address on it. In Mininet-WiFi an access point is a switch in the root namespace with no address of its own, so a role process placed on one has nothing to bind and dies with Cannot assign requested address; keeping the two namespaces apart is what prevents that config from being expressible at all.

type

ap is an access point: the nodes on it are stations, associating over a radio whose wifi parameters govern the whole cell, and each one’s position is what the propagation model acts on. switch is the same idea without radios - a wired shared segment - and goes through the same code rather than a special case.

Shaping is the medium’s own, not a per-link qdisc: a cell’s loss and delay come from the propagation model and the distances, which is why the distances are the axis such an experiment varies. A connector therefore has no distribution, loss or bandwidth_mbps; a path that needs those is a links entry.

class cadet.config.schema.Route(**data)¶

Bases: _Strict

A path from one node to another across several links, in order.

hops names existing links entries, so a hop is a link and a route is an ordering over links: everything that already reads links - the netem rules, the emulated topology, the link report, the feature gate - keeps working on the hops without knowing a route exists.

realise says what a multi-hop path is, which is not something that can be inferred:

compose

One end-to-end connection whose behaviour is the composition of the hops. Nothing runs on the waypoints; they name where the path goes. A composed path cannot queue, cannot drop on a full buffer and cannot be where computation happens.

relay

Each waypoint runs a forwarding stage that receives a message and sends it on, so a hop is a real store-and-forward step with its own queue and its own failure mode. This is what an experiment about the waypoint needs.

via is optional and redundant: when given it must name exactly the waypoints the hops already imply, which makes a route readable without re-deriving it and is checked rather than trusted.

class cadet.config.schema.TransportConfig(**data)¶

Bases: _Strict

Wire transport for node-to-node traffic.

protocol selects the carrier: tcp is a plain socket, websocket wraps the same framing in RFC 6455 binary frames over one HTTP upgrade. mode selects framing: frame sends one length-prefixed message per payload, stream drops the transport’s prefix and lets the receiver find each record’s end in the encoding itself (so it needs encoding: safe).

class cadet.config.schema.EnergyMetrics(**data)¶

interval_ms unset takes the chosen source’s own original cadence: 10 ms for the GPU and Jetson readers, which is what every one of those originals sampled at, and 100 ms for rpi_proxy, which is what its original used. Setting it pins one value for whatever source is chosen.

Loading, overriding, sweeping and identifying CADET configs.

What this is for:

Turns a YAML file into validated Config objects. Applies --set key=value command-line overrides, expands a sweep into one concrete config per parameter combination, and derives a stable run_id and per-repetition seed.

What it contains:

  • load_yaml(), load_config_data() (resolves extends: bases by deep-merge), apply_overrides(), set_by_path()

  • build_config() (dict -> Config)

  • expand_sweep() (base dict -> list of concrete Config)

  • config_hash(), run_id(), seed_for_rep()

  • ConfigError and format_validation_error() for readable errors

How it fits into CADET:

cadet validate (cadet.cli) and, later, the runner/orchestrator call these helpers. Overrides and sweeps are applied to the raw mapping before validation, so every produced config is typed and checked.

How to configure it:

Overrides are dotted.path=yaml_value (list indices allowed, e.g. nodes[1].host=localhost). Sweep axes are the same dotted paths mapped to value lists under sweep.axes.

cadet.config.loader.load_run_configs(path, overrides)¶

Load, override and expand a config file into concrete run configs.

Returns (run_configs, base_config) where base_config is the single pre-expansion config (useful for reporting).

Return type:

Tuple[List[Config], Config]

Parameters:

  • path (str)

  • overrides (List[str])

Implemented-feature gate: which declared options actually work yet.

The schema (cadet.config.schema) deliberately declares the full planned config surface, including options not implemented yet, so configs are forward-compatible and self-documenting. This module is the single place that says which of those options are wired up, so an experiment that asks for an unbuilt feature fails loudly (“not implemented yet: X, planned”) instead of being silently ignored.

Contains IMPLEMENTED (option path to set of built and verified values), EXPERIMENTAL (implemented but unverified; refused by default), and the gate functions unimplemented_features(), experimental_features(), and allow_experimental().

cadet validate and preflight (so cadet run / sweep / emulate) call unimplemented_features() after schema validation and refuse to proceed if it is non-empty. Three tiers exist because two were not enough: a feature that is written but unproven should be refusable by default yet exercisable with an explicit opt-in that is recorded in the run record. A planned option stays refused regardless of the opt-in: there is nothing behind it to run. The opt-in is experiment.allow_experimental in the config, or --allow-experimental on run / sweep / emulate.

cadet.config.implemented.unimplemented_features(config, allow_experimental=False)¶

Return the requested features this codebase will not run.

Each string is a human-readable “<path>=<value>” plus the tier that refused it, so the reader can tell “there is no code for this” from “there is code but you did not opt in”.

allow_experimental accepts the experimental tier. It never accepts the planned tier: there is nothing behind a planned option, so allowing it could only replace a clear refusal with a crash.
